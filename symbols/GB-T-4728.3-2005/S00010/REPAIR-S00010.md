## 缺陷 1（主缺陷）：端子位置错误且无 uuid/名/type，QET 0.90 无法接线

- 原版：10 个 `<terminal>` 只有 `x/y/orientation`，无 uuid、无 name、无 type；且放在 `<description>` 之外、作为 `<definition>` 的直接子元素（本批格式 S00307/S00864/S00017 均把端子放在 `<description>` 内、图形线条之后）。同作者 S00009 的端子在 `<description>` 内（虽也无 uuid），S00010 的位置是本件独有的错误。
- 根因（实测确认）：QET 0.90 只读 `<description>` 内的端子。原版端子在 `<description>` 外，故载入后实例端子为 0。第一版修正只补了 uuid/名/type、未移位置，重测保存后实例端子仍为 0——证明缺 uuid 不是唯一原因，位置错误是主因；补 uuid 仍必要（无 uuid 则导线端点无法在网表中按端子识别，见 S00306 网表“按 definition 端子 UUID 对应”）。
- 证据（本机 QET 0.90，`qet/gb-qet-batch10-S00010-test.qet`）：
  - 载入后 6 个实例均正常渲染，但悬停/选中实例均不显示红色端子标记（端子查找脚本在各缩放截图上均返回 0 个真实端子；同法在 batch9 的 S00306 截图上可检出 10 个）。
  - 选择工具下从 A 实例右端 (272,163) 拖向 B 实例左端 (0,163)，间隙像素计数始终为 0，无导线生成；拖拽改为抓取元件本体（一次误拖使工作目录测试工程中的 A 实例位移 +560/+300，属测试工程伪影，repo 未受影响）。
  - File 菜单保存后（工程版本 0.90），直接解析已保存工程 XML：6 个实例的 `<terminals>` 均为空（各 0 个），无 `<conductors>` 元素；`work/netlist.py` 按已知 bug 在 0 导体时崩溃（`TypeError: 'NoneType' object is not iterable`）。
  - 对照：同法解析 batch9-B 已保存的 S00864 测试工程（定义端子带 uuid）：6 个实例共 12 个端子、导线 1 条。证明端子缺失是定义端子无 uuid 所致，不是测试手法问题。
  - 作者 README 称 0.100.1-dev 上 `--check-elements` 报 `OK (10 terminals)`——该检查只数定义端子个数，不验证 QET 0.90 实例化；导出 PDF 亦无需实例端子，故作者自测未发现。
- 修正：10 个端子移入 `<description>` 内（图形线条之后、`</description>` 之前，与 S00307/S00864 位置一致），并按本批格式补 `uuid`（新生成，互不相同）、`name` 1–10（左 1–5 自上而下、右 6–10 自上而下）、`type="Generic"`；端子坐标、方向、定义 UUID、定义版本 0.5 均不变。属性顺序与 S00017 一致（uuid, name, x, y, orientation, type）。

## 缺陷 2：胶囊偏高约 5 单位

- 原页证据（`orig/p-08.png`，300 dpi，11.811 px/mm，逐像素量取）：
  - 胶囊顶 y=2781、底 y=2862（底弧最低暗行；y=2863–2865 的宽幅暗行是网点底纹，非胶囊），高 81 px = 6.86 mm。
  - 胶囊外宽 44 px = 3.73 mm；胶囊底→第 1 线 63 px = 5.33 mm；胶囊直边长约 40.7 单位（切点间）。
  - 换算（272 单位 = 20.91 mm 线长，13.0 单位/mm）：原页胶囊高 89.2 单位、宽 48.4 单位。
- 原版：胶囊 49 宽 × 94.5 高（顶 y=0.5、底 y=95），高出约 5.3 单位（0.41 mm，约 6%），误差集中在直边段（半径 24.5 单位与实测 24.2 单位一致）。
- 原版 README 称胶囊 7.28 mm——该数与 .elmt 一致，与原页不符（应为 6.86 mm；作者疑把网点底纹行计入胶囊底）。
- 修正：顶弧 12 段整体下移 5 单位（顶端 y 0.5→5.5），直边上端 y 25→30；底弧、直边下端 y=70.5、竖线、箭头尖均不动。修正后胶囊 49 宽 × 89.5 高（3.77×6.88 mm）。
